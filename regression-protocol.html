Part A · Theoretical foundations

0. Principles and the estimand

Every regression answers a question, and the question determines the method. Three goals are commonly confused:

  • Prediction: estimate \(\mathbb{E}[Y \mid X = x]\) or a conditional quantile for new units, and judge the result by out-of-sample loss (Shmueli, 2010; Breiman, 2001).
  • Description or association: summarize how \(\mathbb{E}[Y \mid X]\) varies with \(X\). Coefficients are conditional associations, not effects.
  • Causal effect: estimate what would happen to \(Y\) under an intervention on \(X\), for example \(\mathbb{E}[Y(1) - Y(0)]\) (Hernán and Robins, 2020; Pearl, 2009).

A model can predict well and still give a biased causal estimate, because adjusting for the wrong variables can make bias worse. The protocol therefore requires that the estimand (the population quantity being estimated) be written down before the data are touched.

Formal target

\[ \theta^\star = \arg\min_{\theta} \; \mathbb{E}_{P}\big[ \ell(Y, f_\theta(X)) \big] \]

Here \(\ell\) is the loss, \(P\) is the population the model is meant to serve, and \(\theta^\star\) is the best-approximating parameter under that loss. Choosing \(\ell\) (squared error, absolute error, pinball, log score) defines what "best" means. Choosing \(P\) defines where the result is supposed to hold, which is the source of most external-validity failures.

Expert point. Many failures come from a mismatch between the estimand and the metric. Optimizing RMSE estimates the conditional mean, but a clinical threshold decision may need the conditional probability of exceeding a value, and a capacity planner may need an upper quantile. Choose the functional first, then the loss that is consistent with it (Gneiting and Raftery, 2007).

1. Linear model theory

1.1 Model and estimator

For \(n\) observations, the linear model is \(y = X\beta + \varepsilon\), where \(X\) is \(n \times p\). The ordinary least squares (OLS) estimator is

\[ \hat\beta = (X^\top X)^{-1} X^\top y, \qquad \hat\sigma^2 = \frac{\lVert y - X\hat\beta \rVert^2}{n - p}. \]

Under the Gauss-Markov conditions (linearity in parameters, strict exogeneity \(\mathbb{E}[\varepsilon \mid X] = 0\), no perfect multicollinearity, and \(\operatorname{Var}(\varepsilon \mid X) = \sigma^2 I\)), \(\hat\beta\) is the best linear unbiased estimator (BLUE). Under normal errors it is also the maximum likelihood estimator and has exact \(t\) and \(F\) distributions.

1.3 Asymptotics and robust covariance

Under regularity conditions, \(\sqrt{n}(\hat\beta - \beta) \xrightarrow{d} \mathcal{N}(0, \Sigma)\). The heteroskedasticity-robust (sandwich) covariance is

\[ \widehat{\operatorname{Var}}(\hat\beta) = (X^\top X)^{-1} \Big( \sum_i w_i\, x_i x_i^\top e_i^2 \Big) (X^\top X)^{-1}, \]

with \(w_i = 1\) for HC0 (White, 1980), and \(w_i = 1/(1-h_{ii})^2\) for HC3 (MacKinnon and White, 1985), where \(h_{ii}\) is the leverage. HC3 is the recommended default in small samples because it corrects for the tendency of residuals to understate their variance at high-leverage points.

1.4 Predictive intervals and the difference from confidence intervals

A confidence interval for the conditional mean \(x_0^\top\beta\) has width driven by \(\operatorname{Var}(x_0^\top \hat\beta)\). A prediction interval for a new observation \(y_0\) adds the irreducible noise \(\sigma^2\):

\[ \operatorname{Var}(y_0 - \hat y_0) = \sigma^2 \big(1 + x_0^\top (X^\top X)^{-1} x_0\big). \]

Reporting a confidence band as if it were a prediction band is one of the most common errors in applied work.

2. Bias, variance, and regularization

2.1 Decomposition

For a fixed test point \(x_0\) and a training-set-dependent estimator \(\hat f\),

\[ \mathbb{E}\big[(y_0 - \hat f(x_0))^2\big] = \underbrace{\big(\mathbb{E}[\hat f(x_0)] - f(x_0)\big)^2}_{\text{bias}^2} + \underbrace{\operatorname{Var}[\hat f(x_0)]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{irreducible}}. \]

Flexible models lower bias and raise variance. Regularization deliberately accepts some bias to reduce variance, which lowers total error when the signal-to-noise ratio is modest or the number of predictors is large relative to \(n\) (Hastie, Tibshirani, and Friedman, 2009).

2.2 Penalized estimators

Each penalty solves \(\min_\beta \lVert y - X\beta \rVert^2 + \text{penalty}\), with penalty choices:

  • Ridge (\(\lambda \lVert\beta\rVert_2^2\)): closed form \(\hat\beta_\lambda = (X^\top X + \lambda I)^{-1} X^\top y\). Stable under collinearity; shrinks but does not select (Hoerl and Kennard, 1970).
  • Lasso (\(\lambda \lVert\beta\rVert_1\)): sparse solutions and selection; unstable when predictors are highly correlated (Tibshirani, 1996).
  • Elastic net (\(\lambda[\alpha\lVert\beta\rVert_1 + \tfrac{1-\alpha}{2}\lVert\beta\rVert_2^2]\)): groups correlated predictors and selects; a good default when \(p\) is large (Zou and Hastie, 2005).

Penalized coefficients are biased toward zero. Post-selection inference based on the same data is not valid without specialized methods (Lee et al., 2016), so selection and inference should be separated: select in one sample or fold and estimate in another, or use debiased or double-selection procedures.

2.3 Bayesian view

Ridge is the posterior mode under a Gaussian prior \(\beta \sim \mathcal{N}(0, \sigma^2/\lambda\, I)\), and the lasso corresponds to a Laplace prior. Full Bayesian regression yields a posterior \(p(\beta \mid y)\) that propagates uncertainty without relying on asymptotics, which is valuable with small \(n\) or hierarchical structure (Gelman et al., 2013).

3. Likelihood and generalized models

Choose the distribution to match the outcome, then the link function to match the scale of effects. Fit by maximum likelihood with iteratively reweighted least squares (IRLS).

3.1 Quasi-likelihood

When the mean is correctly specified but the variance is not, quasi-likelihood estimates \(\beta\) consistently with \(\operatorname{Var}(y) = \phi\, V(\mu)\), and the dispersion \(\phi\) is estimated from the data. Use sandwich SEs for robustness (Wedderburn, 1974).

3.2 Quantile regression

For a conditional quantile \(\tau \in (0,1)\), minimize the check (pinball) loss \(\rho_\tau(u) = u(\tau - \mathbf{1}\{u < 0\})\) (Koenker and Bassett, 1978). This describes the whole conditional distribution rather than only its mean, and it is the basis for interval prediction and heteroskedasticity-aware modeling.

3.3 Hierarchical and mixed models

For grouped data \(y_{ij} = x_{ij}^\top\beta + b_j + \varepsilon_{ij}\) with \(b_j \sim \mathcal{N}(0, \tau^2)\), the random effects produce partial pooling: group estimates shrink toward the overall mean in proportion to their noise. Ignoring the grouping gives overly narrow standard errors. Observations within a group are not independent, and the independence assumption must be addressed explicitly.

4. Uncertainty and conformal prediction

4.1 Frequentist, Bayesian, and resampling intervals

Three legitimate routes to uncertainty exist: asymptotic SEs (fast but dependent on the model being right), the bootstrap (Efron and Tibshirani, 1993), and posterior intervals (dependent on the prior and likelihood). Each makes different assumptions; the report should say which was used and why.

4.2 Conformal prediction

Conformal prediction gives distribution-free finite-sample coverage. Given a calibration set and a nonconformity score \(s(x,y) = |y - \hat f(x)|\), let \(q\) be the \(\lceil (n_{\text{cal}}+1)(1-\alpha)\rceil / n_{\text{cal}}\) empirical quantile of the calibration scores. Then the interval \(\hat f(x_0) \pm q\) satisfies

\[ \mathbb{P}\big(Y_{n+1} \in C(X_{n+1})\big) \geq 1 - \alpha \]

whenever the data are exchangeable (Vovk, Gammerman, and Shafer, 2005; Angelopoulos and Bates, 2023). The guarantee is marginal: it averages over \(x\). Coverage can still fail for particular subgroups, so conditional coverage must be checked empirically. Conformalized quantile regression (Romano, Patterson, and Candès, 2019) produces adaptive-width intervals. Under distribution shift or temporal dependence, use weighted or adaptive variants and state the assumption that is in use.

5. Causal identification

A regression coefficient is a causal effect only under explicit assumptions. Write them before estimating:

  • Consistency: the observed outcome under treatment \(a\) equals \(Y(a)\) for units with \(A = a\).
  • Conditional exchangeability (no unmeasured confounding): \(Y(a) \perp A \mid X\).
  • Positivity (overlap): \(0 < \mathbb{P}(A = 1 \mid X) < 1\) for all covariate strata in the population of interest.
  • No interference (SUTVA): one unit's treatment does not change another unit's outcome, or the model accounts for it.

5.1 Graphical criteria

A directed acyclic graph (DAG) encodes these assumptions. The back-door criterion identifies a set \(Z\) that blocks all back-door paths from \(A\) to \(Y\) and contains no descendants of \(A\). Adjusting for mediators blocks the effect of interest; adjusting for colliders opens spurious paths. Covariate selection by p-value or by \(R^2\) is not a substitute for this reasoning.

5.2 Estimators

  • Outcome regression and g-computation: model \(\mathbb{E}[Y \mid A, X]\) and average predictions under each treatment.
  • Propensity methods: weighting, matching, or stratification on \(e(X) = \mathbb{P}(A=1 \mid X)\) (Rosenbaum and Rubin, 1983).
  • Doubly robust estimators: consistent if either the outcome or the propensity model is correct (Robins, Rotnitzky, and Zhao, 1994; Bang and Robins, 2005).
  • Double/debiased machine learning: cross-fitted nuisance estimates with Neyman-orthogonal scores allow flexible adjustment while keeping \(\sqrt{n}\)-consistent inference for a low-dimensional parameter (Chernozhukov et al., 2018).
  • Quasi-experimental designs: difference-in-differences (with parallel-trends evidence), regression discontinuity, instrumental variables (with a first-stage F above about 10 as a rough guide, and an exclusion restriction argued from theory), and synthetic control (Angrist and Pischke, 2009; Cunningham, 2021).

5.3 Sensitivity to unmeasured confounding

For a risk ratio \(RR \geq 1\), the E-value is \(E = RR + \sqrt{RR(RR - 1)}\), the minimum strength of association that an unmeasured confounder would need with both treatment and outcome to explain away the estimate (VanderWeele and Ding, 2017). Report it alongside the estimate, and interpret it cautiously.

6. Validity and evaluation theory

6.1 Types of validity

  • Internal validity: is the estimate correct for the sample studied (no leakage, correct specification, adequate adjustment)?
  • Statistical conclusion validity: are the uncertainty statements correct (SEs, tests, interval coverage)?
  • External validity: does the result transport to other populations, sites, or times? This is often the weakest link (Steyerberg, 2019).
  • Construct validity: do the measured variables represent the intended concepts?

6.2 Proper scoring rules

A scoring rule \(S(F, y)\) for a predictive distribution \(F\) is proper if its expected value is uniquely minimized (or maximized) by the true distribution. Examples include the log score \(-\log f(y)\) and the continuous ranked probability score (CRPS). Improper rules can reward miscalibrated forecasts, so they should not be used alone. Calibration (agreement between predicted and observed frequencies) and sharpness (concentration of the predictions) should be reported together.

6.3 Comparing two models

For paired forecast losses \(d_t = L(e_{1t}) - L(e_{2t})\), the Diebold-Mariano statistic is \(\text{DM} = \bar d / \sqrt{\widehat{\operatorname{LRV}}/T}\), where \(\widehat{\operatorname{LRV}}\) is a long-run variance estimate (Diebold and Mariano, 1995). Cross-validation folds are not independent, so paired fold comparisons should be interpreted with corrected tests or with nested designs.

On p-values. A p-value is the probability of data at least as extreme as observed, under a stated model and null. It is not the probability that the hypothesis is true, and it does not measure effect size. The ASA statement (Wasserstein and Lazar, 2016) and its follow-up (Wasserstein, Schirm, and Lazar, 2019) remain the standard references. Report effect sizes with intervals and treat thresholds as one input among several.

Part B · The protocol, stage by stage

Stage 0. Pre-registration and scope

Purpose: fix the question, the estimand, the metric, and the baseline before outcome data are examined, to limit the garden of forking paths (Gelman and Loken, 2013; Nosek et al., 2018).

  1. State the goal: prediction, association, or causal effect (Section 0).
  2. Define the target variable, its scale, support, and any censoring or truncation.
  3. Define the unit of analysis and the target population \(P\).
  4. Set the primary metric, the secondary metrics, and the naive baseline (mean predictor, last value, or a simple OLS on the key covariates).
  5. Record decision impact: what action follows, and the asymmetry of errors.
  6. For prediction models, do a sample-size justification (Riley et al., 2020) rather than a rule of thumb.
  7. Lock the analysis plan in a dated, versioned file. Record any later deviation with a reason.
Gate. Question, estimand, target, metric, baseline, and sample-size rationale are written and dated.

Stage 1. Data governance and provenance

Purpose: ensure the data may be used, are traceable, and can be defended.

  1. Lineage: source, extraction date, query text, and every transformation, in code.
  2. Privacy: identify personal data and apply the relevant regime (GDPR, HIPAA, FERPA, CCPA). Use the minimum necessary fields, de-identification (Safe Harbor or Expert Determination under HIPAA), and access controls.
  3. Licensing and consent: confirm the terms of use, particularly for scraped data, survey microdata, and third-party platforms.
  4. Data contracts: define schema, types, units, ranges, and freshness; enforce them with the R packages pointblank or validate (or dbt tests for SQL pipelines).
  5. Complex survey data: retain the sampling weights, strata, and clusters, and analyze with design-based methods (Lumley, 2010), not as simple random samples.
Gate. Provenance documented; privacy, licensing, and survey design recorded.

Stage 2. Data audit and exploratory analysis

Purpose: find errors, missingness, and leakage before they shape the model.

  1. Structure: row and column counts, dtypes, duplicate keys, and unit consistency.
  2. Missingness mechanisms: MCAR, MAR, or MNAR (Little and Rubin, 2019). Use Little's MCAR test (Little, 1988; naniar::mcar_test() in R) as one input and reason about the mechanism substantively. Missingness indicators regressed on observed variables indicate MAR-compatible structure. MNAR cannot be tested from the data and requires sensitivity analysis.
  3. Errors and sentinels: impossible values, unit-entry errors, codes such as -999 or 9999. Separate errors (correct or drop) from genuine extremes (keep and model).
  4. Target distribution: skewness, bounds, zero mass, and heaping.
  5. Nonlinearity: LOESS or binned means against each predictor; partial residual plots.
  6. Collinearity: correlation matrix and variance inflation factors \(\text{VIF}_j = 1/(1-R_j^2)\). VIF above about 5 to 10 warrants action, but the appropriate threshold depends on the inferential target.
  7. Leakage scan: flag any feature computed from, or recorded after, the outcome. Leakage is the most frequent cause of implausibly strong results (Kapoor and Narayanan, 2023).
  8. Structure: time ordering, repeated measures, clusters, and drift across periods.
Gate. Data issues logged with decisions; leakage candidates resolved.

Stage 4. Preprocessing as a pipeline

Purpose: every data-dependent step (imputation, scaling, encoding, selection) is estimated inside training folds only.

  1. Imputation: median or mode for simple cases; iterative imputation (MICE; van Buuren, 2018) under MAR. For inference, multiply impute with \(m \geq 20\) imputations and pool with Rubin's rules: total variance \(T = \bar U + (1 + 1/m) B\), where \(\bar U\) is the mean within-imputation variance and \(B\) the between-imputation variance (Rubin, 1987).
  2. Categorical encoding: one-hot for low cardinality; out-of-fold target encoding with smoothing for high cardinality; explicit handling of unseen categories.
  3. Scaling: standardize for penalized and gradient-based models; not required for trees.
  4. Nonlinear terms: natural splines or GAM smooths with penalties, rather than ad hoc high-order polynomials.
  5. Transformations: log or Box-Cox (Box and Cox, 1964) for positive predictors; Yeo-Johnson for data with zeros or negatives. Interpret coefficients on the transformed scale and report back-transformed effects where needed.
  6. Feature engineering: interactions justified by theory; ratios with explicit units. Avoid searching large interaction spaces without correction (Kuhn and Johnson, 2019).
  7. Outliers: winsorize only with a written rationale; prefer robust scaling or robust estimators.
Gate. Pipeline runs end to end on each training fold, with no information from validation folds.

Stage 5. Model ladder

Purpose: compare models from simple to flexible, under the same splits, and always beside the baseline.

  1. Baseline: mean or median predictor; OLS on the key covariates.
  2. GLMs: family chosen per Section 3.
  3. Penalized linear models: ridge, lasso, elastic net, tuned by CV.
  4. Robust regression: Huber M-estimation (Huber, 1964) or RANSAC when outliers are real; report sensitivity against OLS.
  5. Quantile regression: for conditional quantiles and interval prediction.
  6. GAMs: penalized smooths with interpretable nonlinear effects (Wood, 2017).
  7. Gradient-boosted trees: XGBoost (Chen and Guestrin, 2016) via the xgboost R package, or LightGBM and CatBoost, which also have R interfaces, for complex tabular structure; monotone constraints where theory requires them. Gradient boosting itself is due to Friedman (2001).
  8. Random forests: Breiman (2001); useful as a benchmark with little tuning.
  9. Hierarchical and Bayesian models: mixed models for nesting; Stan (Carpenter et al., 2017) through cmdstanr, or brms (Bürkner, 2017) for full posterior inference.
  10. Time-series regression: ARIMAX, state-space, or regression with ARIMA errors when temporal dependence is central (Hyndman and Athanasopoulos, 2021).
Selection rule. Prefer the simplest model whose CV error lies within one standard error of the best (Hastie et al., 2009, one-SE rule), unless the decision requires the extra accuracy and the gain is material relative to the decision costs.
Gate. Baseline and at least three model families evaluated on identical folds.

Stage 6. Tuning and nested validation

Purpose: avoid optimistic bias from choosing hyperparameters and reporting performance on the same data.

  1. Use Bayesian optimization (tune_bayes() in tidymodels; Snoek et al., 2012) or random search (tune_grid() with grid = 25, or grid_random(); Bergstra and Bengio, 2012). Grid search is rarely efficient.
  2. Use nested CV when an unbiased performance estimate is required: an outer loop for evaluation, an inner loop for tuning.
  3. Log every trial with seed, parameters, fold scores, and runtime.
  4. Limit the number of configurations compared, and report the spread across folds, not only the mean.
Gate. Final hyperparameters chosen from training data only; test set untouched.

Stage 9. Inference and uncertainty

Purpose: quantify uncertainty correctly for the quantity being reported.

  1. Standard errors: HC3 under heteroskedasticity; cluster-robust with an adequate number of clusters (Cameron, Gelbach, and Miller, 2008 discuss small-cluster corrections); Newey-West (Newey and West, 1987) for autocorrelation.
  2. Intervals: distinguish confidence intervals for means from prediction intervals for new observations.
  3. Bootstrap: pairs bootstrap for regression; wild cluster bootstrap for few clusters; block bootstrap for dependence.
  4. Conformal intervals: split or CV+ conformal for distribution-free marginal coverage; check conditional coverage across subgroups (Section 4.2).
  5. Multiple testing: control the false discovery rate with Benjamini-Hochberg (Benjamini and Hochberg, 1995) for screening; apply familywise correction for a small confirmatory set.
  6. Effect sizes: report standardized or unstandardized effects with units and intervals. A statistically significant trivial effect is not a finding.
  7. Bayesian reporting: posterior summaries and intervals, prior sensitivity, and convergence diagnostics (rank-normalized \(\hat R < 1.01\), effective sample size, and divergence counts; Vehtari et al., 2021).
Gate. Inference method matches the data structure; intervals labeled correctly.

Stage 10. Causal analysis

Purpose: support claims about effects only where identification is credible.

  1. Draw the DAG and state the adjustment set. Justify each covariate by its causal role.
  2. State and assess consistency, exchangeability, positivity, and no interference (Section 5). Show overlap diagnostics: propensity distributions, standardized mean differences after weighting.
  3. Choose a design: randomized experiment, DiD with pre-trend tests, RDD with bandwidth sensitivity, IV with exclusion argued, synthetic control, or DML with cross-fitting.
  4. Report the estimand explicitly (ATE, ATT, ATE in a subgroup, or a conditional effect) and the target population.
  5. Sensitivity analysis: E-values (VanderWeele and Ding, 2017), Rosenbaum bounds (Rosenbaum, 2002), or omitted-variable bounds (Cinelli and Hazlett, 2020).
  6. Heterogeneous effects: pre-specify subgroups; use honest estimators such as causal forests (Wager and Athey, 2018); correct for multiplicity.
Gate. Identification assumptions stated, assessed, and tested as far as the data allow.

Stage 11. Robustness and stress testing

Purpose: show whether the conclusion depends on arbitrary analytic choices.

  1. Specification curve or multiverse analysis (Simonsohn, Simmons, and Nelson, 2020): vary reasonable choices (covariates, transformations, exclusions, estimators) and show the distribution of estimates.
  2. Influence: drop top-influence observations and re-estimate; check the stability of signs and magnitudes.
  3. Alternative estimators: OLS, robust, penalized, and tree-based estimates should be compared; disagreement needs explanation.
  4. Distribution shift: evaluate on held-out sites, periods, or simulated shifts (for example, covariate shift reweighting).
  5. Perturbation sensitivity: how predictions move under small input perturbations or measurement error.
  6. Simulation checks: generate data from the fitted model and verify that the procedure recovers known parameters and nominal coverage (Morris, White, and Crowther, 2019).
Gate. Key conclusions are stable across the pre-specified specification set, or instability is reported.

Stage 12. Fairness, bias, and ethics

Purpose: identify and document who bears the errors and whether they are systematically distributed.

  1. Subgroup performance: errors, calibration, and coverage by relevant groups, where lawful and appropriate.
  2. Disparity criteria: calibration within groups, equalized error rates, and demographic parity. These criteria generally cannot all hold simultaneously unless base rates are equal or the predictor is perfect (Kleinberg, Mullainathan, and Raghavan, 2017; Chouldechova, 2017). Choose the criterion that matches the decision and justify it.
  3. Proxy check: test whether permitted features reconstruct protected attributes.
  4. Impact review: document who is affected by errors, whether a human review step is needed, and whether there is recourse.
  5. Frameworks: NIST AI Risk Management Framework 1.0 (2023); EU Artificial Intelligence Act, Regulation (EU) 2024/1689; sector rules such as ECOA and fair lending in finance; FDA, Health Canada, and MHRA guiding principles for machine learning in medical devices (2021); Federal Reserve SR 11-7 on model risk management (2011). Verify current status before relying on any of these.
Gate. Group-level results and the chosen fairness criterion documented, with review sign-off.

Stage 13. Final test evaluation

Purpose: give one honest estimate of performance on the sealed test set.

  1. Retrain the selected model on the full development data with frozen hyperparameters.
  2. Evaluate once on the sealed test set.
  3. Report all pre-registered metrics; label any exploratory metrics as exploratory.
  4. Do not revise the model after seeing test results. If you must, treat the outcome as a new study with fresh data.
Gate. Test results reported as pre-registered, with no iteration on the test set.

Stage 14. Reproducibility and versioning

Purpose: make every result rerunnable by someone else.

  1. Environment: pinned dependencies (lockfile, Docker, or Nix). Record hardware where floating-point determinism matters.
  2. Randomness: set and log seeds for splits, initialization, bootstrap, and sampling.
  3. Code and data: version control with Git; data snapshots and hashes with DVC, LakeFS, or Delta Lake.
  4. Experiment tracking: MLflow (which has an R client), Weights and Biases, or Neptune.
  5. Model registry: staging, production, and archived states, with approval records.
  6. Independent rerun: a second person reproduces the headline results from the repository. Record the result.
  7. Technical debt: review pipelines for hidden dependencies and configuration coupling (Sculley et al., 2015).
Gate. Headline results reproduced from a clean environment by an independent run.

Stage 15. Reporting

Purpose: give readers what they need to judge validity and to reuse the work.

Use the relevant guideline:

  • TRIPOD+AI (Collins et al., 2024) for prediction models in health; TRIPOD (Collins et al., 2015) for the earlier version.
  • STROBE (von Elm et al., 2007) for observational studies.
  • CONSORT (Schulz et al., 2010) for randomized trials.
  • Model cards (Mitchell et al., 2019) and datasheets for datasets (Gebru et al., 2021) for models and data in production.

A complete report contains: the pre-registered question and any deviations; data description, provenance, and flow; missingness; preprocessing and modeling choices with justification; the baseline and all candidate models with CV results; final test results with intervals; diagnostics, robustness, and subgroup results; limitations and threats to validity; intended and out-of-scope use; code, data access statement, and reproduction instructions.

Gate. Reporting checklist completed; limitations stated plainly.

Stage 16. Deployment and monitoring

Purpose: keep a model valid after it leaves the development environment.

  1. Serving: batch or real-time, with the same validation logic as training.
  2. Data drift: population stability index \(\text{PSI} = \sum_k (a_k - e_k)\ln(a_k/e_k)\), where \(a_k\) and \(e_k\) are the actual and expected bin proportions; values above about 0.2 are a common alert threshold (Siddiqi, 2006). Add KS tests for continuous features.
  3. Concept drift: track the relationship between inputs and outcomes as labels arrive (Gama et al., 2014). Use rolling-window metrics and a predefined retraining trigger.
  4. Coverage and calibration monitoring: interval coverage and calibration slope by subgroup over time.
  5. Shadow and canary deployment: run the candidate beside the incumbent before switching.
  6. Rollback: keep the previous version deployable and tested.
  7. Revalidation: scheduled review (for example, quarterly), with a logged decision to retrain, recalibrate, or retire.
Gate. Monitoring, alert thresholds, retraining triggers, and rollback tested before go-live.

Reference pipeline (R)

This pipeline enforces the rule that splitting comes before preprocessing, compares a baseline with two candidates on identical folds, applies the one-SE rule, and evaluates the test set once. Replace dat and the splitting strategy to match Stage 3.

library(tidymodels)   # rsample, recipes, parsnip, tune, yardstick, workflows
library(glmnet)       # elastic net engine
library(xgboost)      # gradient boosting engine

SEED <- 42
set.seed(SEED)

# dat: data frame with outcome column `y` and predictors.
# Split BEFORE any fitting. For grouped or time-ordered data, see Stage 3
# (group_vfold_cv() or rolling_origin() from rsample).
split <- initial_split(dat, prop = 0.85, strata = y)
dev   <- training(split)
test  <- testing(split)     # sealed until the final step

folds   <- vfold_cv(dev, v = 5, strata = y)
metrics <- metric_set(rmse, mae, rsq)

# Preprocessing is a recipe: it is estimated inside each training fold only.
rec <- recipe(y ~ ., data = dev) |>
  step_impute_median(all_numeric_predictors()) |>
  step_impute_mode(all_nominal_predictors()) |>
  step_novel(all_nominal_predictors()) |>     # handles unseen factor levels
  step_dummy(all_nominal_predictors()) |>
  step_zv(all_predictors()) |>
  step_normalize(all_numeric_predictors())

# Candidate 0: baseline (predicts the training mean)
baseline_wf <- workflow() |>
  add_recipe(rec) |>
  add_model(null_model() |> set_engine("parsnip") |> set_mode("regression"))

# Candidate 1: elastic net, tuned over penalty and mixture (alpha)
enet_spec <- linear_reg(penalty = tune(), mixture = tune()) |>
  set_engine("glmnet") |>
  set_mode("regression")
enet_wf <- workflow() |> add_recipe(rec) |> add_model(enet_spec)

# Candidate 2: gradient-boosted trees
gbm_spec <- boost_tree(trees = tune(), learn_rate = tune(),
                       tree_depth = tune(), min_n = tune()) |>
  set_engine("xgboost") |>
  set_mode("regression")
gbm_wf <- workflow() |> add_recipe(rec) |> add_model(gbm_spec)

# Cross-validated comparison on the development data only
base_res <- fit_resamples(baseline_wf, resamples = folds, metrics = metrics)
enet_res <- tune_grid(enet_wf, resamples = folds, grid = 25, metrics = metrics)
gbm_res  <- tune_grid(gbm_wf,  resamples = folds, grid = 25, metrics = metrics)

# Best RMSE per candidate, with its standard error across folds
best_rmse <- function(res, name) {
  collect_metrics(res) |>
    filter(.metric == "rmse") |>
    slice_min(mean, n = 1) |>
    transmute(model = name, RMSE = mean, SE = std_err)
}

cv_table <- bind_rows(
  best_rmse(base_res, "baseline_mean"),
  best_rmse(enet_res, "elastic_net"),
  best_rmse(gbm_res,  "xgboost")
) |> arrange(RMSE)
print(cv_table)

# One-SE rule for the elastic net: the simplest (most penalized) setting
# whose RMSE lies within one standard error of the best.
best_enet_1se <- select_by_one_std_err(enet_res, desc(penalty), metric = "rmse")
print(best_enet_1se)

# Final step, run ONCE after the model has been chosen by CV:
# last_fit() refits on the development data and scores the sealed test set.
final_wf  <- finalize_workflow(enet_wf, best_enet_1se)
final_fit <- last_fit(final_wf, split, metrics = metrics)
collect_metrics(final_fit)
Note on the one-SE rule. select_by_one_std_err() applies the rule to the elastic net grid. Fold scores are not independent, so treat the rule as guidance for judgment rather than an automatic decision. The last_fit() call at the end should run only once.

Diagnostics and inference code

The block below fits a linear model, reports HC3 inference, and runs the diagnostic battery from Stage 8.

library(car)       # vif()
library(lmtest)    # bptest(), resettest(), dwtest(), coeftest()
library(sandwich)  # vcovHC()

# Numeric-only development data for the classical linear model
# (dplyr verbs come from tidymodels, loaded in the reference pipeline)
dev_num <- dev |> select(where(is.numeric)) |> drop_na()
ols <- lm(y ~ ., data = dev_num)
summary(ols)

# Robust inference: HC3 sandwich SEs (MacKinnon and White, 1985)
coeftest(ols, vcov = vcovHC(ols, type = "HC3"))

# Collinearity
vif(ols)

# Heteroskedasticity (Breusch-Pagan)
bptest(ols)

# Functional form (RESET, using powers of the fitted values)
resettest(ols, power = 2:3, type = "fitted")

# Autocorrelation (meaningful only if rows are in time order)
dwtest(ols)

# Influence: Cook's distance, with the 4/n flag as a screening convention
cd <- cooks.distance(ols)
which(cd > 4 / nrow(dev_num))

# Standard diagnostic plots: residuals vs fitted, Q-Q, scale-location, leverage
par(mfrow = c(2, 2))
plot(ols)
par(mfrow = c(1, 1))
Why these diagnostics matter. HC3 SEs address heteroskedasticity in the reported inference. A significant RESET test means the linear form is wrong, and HC3 does not fix that: the remedy is a different functional form (Stage 5). The 4/n Cook's distance threshold is a convention for flagging records, not a rule for deletion.

Conformal and bootstrap code

Split conformal prediction

# Split conformal prediction (Vovk et al., 2005; Angelopoulos and Bates, 2023)
set.seed(SEED)
n_dev   <- nrow(dev_num)
cal_idx <- sample.int(n_dev, size = floor(0.25 * n_dev))
tr_set  <- dev_num[-cal_idx, ]
cal_set <- dev_num[cal_idx, ]

fit_tr <- lm(y ~ ., data = tr_set)

alpha  <- 0.10                                  # target 90% marginal coverage
scores <- abs(cal_set$y - predict(fit_tr, cal_set))
n_cal  <- length(scores)

# Finite-sample corrected quantile level, capped at 1
level <- min(ceiling((n_cal + 1) * (1 - alpha)) / n_cal, 1)
q_hat <- quantile(scores, probs = level, type = 1, names = FALSE)

# Evaluate on the sealed test set
test_num <- test |> select(where(is.numeric)) |> drop_na()
pred  <- predict(fit_tr, test_num)
lower <- pred - q_hat
upper <- pred + q_hat
covered  <- test_num$y >= lower & test_num$y <= upper
coverage <- mean(covered)
width    <- mean(upper - lower)
cat(sprintf("Empirical coverage: %.3f (target %.2f); mean width: %.2f\n",
            coverage, 1 - alpha, width))

Paired bootstrap and Diebold-Mariano comparison

Comparing two models on the same test set is a paired problem. Resampling test units jointly preserves the pairing.

# Paired bootstrap for RMSE(A) - RMSE(B) on the same test units
rmse <- function(e) sqrt(mean(e^2))

paired_boot_rmse_diff <- function(y, pred_a, pred_b, B = 5000, seed = SEED) {
  set.seed(seed)
  n     <- length(y)
  point <- rmse(y - pred_a) - rmse(y - pred_b)
  boots <- replicate(B, {
    i <- sample.int(n, n, replace = TRUE)   # resample units jointly: pairing kept
    rmse(y[i] - pred_a[i]) - rmse(y[i] - pred_b[i])
  })
  list(estimate = point,
       ci95 = quantile(boots, c(0.025, 0.975), names = FALSE))
}

# Example, using predictions on the sealed test set:
# res <- paired_boot_rmse_diff(test_num$y, pred_model, pred_baseline)
# res$estimate; res$ci95

# Diebold-Mariano test on the loss differential of two forecasts (Section 6.3).
# Use h equal to the forecast horizon; h = 1 for one-step or i.i.d. settings.
library(forecast)
e1 <- test_num$y - pred_model
e2 <- test_num$y - pred_baseline
dm.test(e1, e2, alternative = "two.sided", h = 1, power = 2)
Caveat. A paired bootstrap on test units treats them as independent. For clustered or time-ordered data, resample clusters or blocks instead (Stage 9). For time-ordered forecasts, the Diebold-Mariano test (Section 6.3) is the more appropriate comparison.
